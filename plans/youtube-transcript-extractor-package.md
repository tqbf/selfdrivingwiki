# YouTube transcript extractor package

Status: implemented on `feature/youtube-transcript-extractor-package`, stacked on
`feature/apple-ttml-extractor-package` (#1211, and transitively #1210).

## Summary

YouTube transcripts now run through a reviewed, digest-pinned extractor
package, the same way PDF, HTML, DOCX, RSS podcast, and Apple Podcasts
transcripts already do. The app and the daemon queue providers resolve the
same selection state machine, execute one protocol revision 3 `remote-url`
operation, and persist exact installed-package provenance.

The direct path this replaces:

- `YouTubeTranscriptService` spawned the raw `tools/youtube-transcript`
  script through `TranscriptSubprocess` and wrote `.builtInTool(.youtubeCaptions)`
  provenance.
- `WikiStoreModel.transcribe` fetched directly for `.youtube` sources while
  podcast sources went through the queue.

Both paths are gone. New YouTube transcripts always carry package provenance.
Historical `.youtubeCaptions` rows still decode and display.

## The package

- Directory: `ExtractorPackages/YouTubeTranscript`
- Package ID: `org.selfdrivingwiki.youtube-transcript`, version 1.0.0
- Manifest revision 1, protocol revision 3
- Launch: `uv run --script bin/youtube-transcript-extractor` (runtime mode;
  the entry point is generated by `scripts/sync-extractor-packages.sh` and
  loads the reviewed script beside it)
- Capability: `network` only
- Registration: ID `captions`, kind `youtube-transcript`, MIME `video/youtube`
- Source: `tools/youtube-transcript/youtube-transcript` (copied into the
  package; `sources.lock.json` pins its digest)
- Dependency: `youtube-transcript-api` (MIT, resolved by uv at first run; no
  third-party code is bundled)

## What the package does

One request enters the process; one terminal frame exits. The request
carries one validated HTTP(S) URL and no input bytes.

1. Validate the request before any network work: protocol revision, kind,
   MIME, `remote-url` transport, no `inputPath`, URL policy (HTTP/HTTPS, no
   credentials, no fragment, at most 2048 bytes), a safe relative output
   path, and a positive deadline.
2. Normalize the URL to a typed 11-character video ID. Accepted forms:
   watch, `youtu.be`, Shorts, embed, and mobile (`m.youtube.com`). A
   non-YouTube host, a malformed URL, or an invalid ID is a typed failure.
   The package never echoes the input URL.
3. Fetch the captions YouTube exposes through `youtube-transcript-api`. The
   library prefers manually created captions over auto-generated ones; if
   the preferred language has no track, the package falls back to the first
   available track. The language default stays `en` with English variants —
   the protocol carries no language option.
4. Consume caption segments under package-owned bounds with incremental
   UTF-8 byte accounting, and write the Markdown atomically to the
   host-provided output path. A partial file never survives a failure.
5. Emit fixed progress frames and exactly one terminal result frame. The
   result metadata reports the stable tool name, the selected language, and
   the generated/manual status the library exposes.

### Bounds

The script owns named bounds that equal or tighten the manifest limits. A
parity test (`tests/test_protocol.py::TestManifestParity`) fails when either
side drifts.

| Bound | Value |
| --- | --- |
| Request document | 1 MiB (manifest `maximumInputByteCount`) |
| Markdown output | 32 MiB (manifest `maximumMarkdownOutputByteCount`) |
| Progress frames | 64 (manifest `maximumProgressEventCount`) |
| Duration | 5 minutes (manifest `maximumDurationMilliseconds`) |
| One caption segment | 4096 UTF-8 bytes |
| Caption segments | 200000 |
| Output headroom | 65536 bytes reserved for headers and separators |

The package checks the deadline before network access, at caption
selection, during segment consumption, after formatting, and before
publication.

### Failure mapping

Every retrieval failure maps to a stable, bounded cause. Messages are fixed
strings: no URL, no video ID, no upstream error text, no paths.

| Condition | Cause |
| --- | --- |
| No caption track | `unsupported-input` |
| Captions disabled | `unsupported-input` |
| Video unavailable | `unsupported-input` |
| Non-YouTube or malformed source URL | `unsupported-input` |
| Invalid video ID | `invalid-request` |
| Protocol/transport/path/deadline violations | `invalid-request` |
| Blocked or rate-limited request | `extraction-failure` |
| Network or library failure | `extraction-failure` |
| Malformed or oversized caption data | `extraction-failure` |
| Passed deadline | `timeout` |

### Explicit boundaries

The package does not download media, does not run speech-to-text, and does
not add Whisper or YouTube OAuth. A video with no available captions is a
typed failure, never a transcription job. The upstream library uses an
undocumented YouTube interface; YouTube can change it or block requests.
The package reports those conditions as bounded failures instead of hiding
them.

## The host route

`ExtractorKind.youtubeTranscript` (`youtube-transcript` on the wire) joins
the closed kind set, with the canonical route
`youtube-transcript` / `video/youtube`. The route follows the established
shape:

- `ProcessPackageYouTubeTranscript` is the provenance-carrying adapter,
  parallel to the RSS and Apple Podcasts adapters.
- `prepareYouTubeTranscript()` resolves through the generic selection state
  machine: the reviewed package is the bundled default, an explicit `none`
  disables the route, and an unavailable saved identity fails closed with
  one redacted diagnostic. No host code branches on the package ID or the
  kind to choose policy.
- Extraction Settings shows a standard route row ("YouTube transcript") with
  the explicit choice "No default (disable YouTube transcripts)". No bespoke
  control was added.
- `default-routes.json` ships the reviewed lineage as the fresh-install
  default.

## Queue execution and persistence

Both `AppQueueExtractionProvider` and `DaemonQueueExtractionProvider` treat
`.youtube` like the podcast routes:

- `YouTubeSourceURL.resolveOperationURL` resolves the operation input. The
  stored plan URL wins when it validates, so watch, `youtu.be`, Shorts, and
  embed rows keep their source contracts. A legacy row with a valid video
  ID but no usable plan URL resolves to the canonical
  `https://www.youtube.com/watch?v=<id>` at the external-format boundary.
  Any other shape returns nil: invalid data never launches a package.
- The prepared adapter executes with progress forwarding and returns
  installed-package provenance plus the package-reported metadata
  (`toolName`, `language`, `transcriptGenerated`).
- Persistence matches the podcast routes: `.transcript` origin, exact
  revision/registration/protocol/metadata provenance, and the immutable
  initial source-content version link. Re-transcription appends an
  alternative; failures write nothing.
- `WikiStoreModel.transcribe` is pure dispatch for all three transcript
  providers and throws `.transcriptQueueRequired` (renamed from
  `.podcastQueueRequired`). The Transcribe button's availability is
  route-derived, not "no signing helper, so always on".

## Tests

- `tools/youtube-transcript/tests/` covers protocol decoding, URL forms,
  selection behavior, bounds, redaction, deadline seams, atomic
  publication, every failure class, and the manifest-parity gate. All tests
  are offline and mock the library.
- `ReviewedExtractorPackageTests` validates the committed package bytes and
  replays recorded success, no-caption, and blocked-request frames through
  `protocol-smoke`.
- `YouTubeQueueExtractionProviderTests` drives the real app and daemon
  provider arms against a faked executor and asserts request shape,
  provenance, and the initial-version link.
- `ExtractorCompositionBoundaryTests` fails if production code constructs
  the removed service, launches the raw script, or records new
  `.builtInTool(.youtubeCaptions)` results.
- `ExtractorKindNeutralityContractTests` extends the data-driven
  registration rules to the YouTube kind and package ID.
