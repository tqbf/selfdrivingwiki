# Agent sandbox scoping Phase 2

## Progress

Phase 2 of `plans/agent-sandbox-scoping.md` is implemented on `feature/agent-sandbox-scoping` (PR #1470). Scoped production launches remain DISABLED; managed-run wiring and credential delivery stay with Phase 3. The plan's Phase 2 section records the deviations; this note records what landed and how it was proven.

Per-run endpoints. `DaemonRunEndpointName` is a fresh 96-bit opaque token from the system random source — deliberately not the run id, so neither value leaks the other. The registry lease now stores the run's endpoint identity. `DaemonRunRegistrationBroker.launchScopedRun` performs the trusted-owner sequence in one call: mint the endpoint name, compose `<container>/r/<name>.sock`, length-validate the complete UTF-8 path BEFORE any registration, register the run (`prepared`), bind the listener, activate the lease. A failed bind revokes the fresh lease before it throws, so no active authority is ever left without its endpoint. `revoke(runID:)` is idempotent over both the registry and the listener; it unlinks the endpoint, which then answers ENOENT. `DaemonRunSocketListener` captures the immutable run id at construction and stamps `.scopedRun` on every accepted connection; it reuses `DaemonSearchSocketServer`'s whole connection machine (same-user getpeereid gate before the first byte, 4 MiB frame cap, per-phase deadlines, one request and one reply per connection) through a new `runEndpointPath:` initializer. Run endpoints never stale-unlink: any pre-existing file at the path fails the bind with the new typed `endpointInUse` error. The ordinary CLI socket's `pathTooLong` error now names the operator fix (#1468): a shorter App Group id or container location.

Trusted registration broker. The broker is an in-process actor with no wire surface — no domain family reaches registration, renewal, or revocation. Before gating it, we audited the existing XPC channel for the §5 separate-app-host case: `WikiDaemonListenerDelegate.listener(_:shouldAcceptNewConnection:)` performs no peer validation at all (no audit token, no code-signing check, no uid check; it accepts every connection unconditionally). The channel is therefore NOT an authenticated control channel, and registration stays in-process only. Exposing it to a separate app host requires XPC peer validation first, and a managed launch must stop rather than fall back when that authentication fails.

The Seatbelt endpoint gate — THE RUNTIME GATE — PASSED. `SandboxProfile.scopedRunInvocation` (and the strict variant) emit the §8 profile: no `WIKI_DB`/`QUEUE_DB` grants, scratch and runtime allowances unchanged, then a terminal section — read AND write denies over the whole App Group container subtree, `network-outbound` denies on the ordinary endpoint and the entire runs directory, and the assigned endpoint's allow as the LAST rule. We proved the shape with real `sandbox-exec` children and real listeners before building on it (macOS 27.0.1, arm64), then locked the same proof into `ScopedSandboxGateTests`: the sandboxed child connects to its assigned endpoint and completes a framed v2 credentialed request; the ordinary endpoint and a sibling run's endpoint are connect-denied with EPERM while both listeners are live; a symlink from a writable path to a denied socket is denied with it (the matcher resolves the vnode), while an alias to the assigned endpoint connects; sqlite3 reads and writes of wiki A, wiki B, and the central queue database, plus registry JSON and WAL sidecar reads, are kernel-denied; scratch writes still work. ECONNREFUSED is explicitly rejected as evidence — a dead listener would refuse, not deny.

Direct database denial rides the same terminal section and the same live suite: both wikis' databases deny reads and writes, the queue database denies writes with no persisted row (the old #1314 channel is closed), the registry file denies reads, and the WAL sidecar denies reads.

One live-test lesson is worth keeping: a probe path longer than `sockaddr_un`'s 103-byte budget fails with ENOENT — silent truncation, not a policy outcome. The symlink probes therefore live at a short global-temp path; the fixture scratch path itself (~114 bytes) would have faked a pass or a fail.

## Verification

- Raw spike first (the gate decision): three live listeners under a fake container; unsandboxed control connected to all three; the profiled child got EPERM on the ordinary endpoint and a foreign run endpoint, CONNECT-OK on the assigned one; symlink to a denied socket EPERM, symlink to the assigned endpoint CONNECT-OK; sqlite3 read/write, registry read, and container write all kernel-denied; scratch write worked.
- `DaemonRunEndpointTests` (6 tests): launch binds + activates, scoped enqueue persists the wiki job, second bind of a live endpoint fails closed, leftover file blocks a bind, revocation unlinks idempotently (registry lease revoked, sibling endpoint untouched), foreign-run capability is `authorizationInvalid`, overlong path fails before registration with no lease left and the #1468 guidance in the message.
- `ScopedSandboxGateTests` (5 live tests, real `sandbox-exec` + real broker endpoints + real fixture daemon): all green — assigned connect + credentialed request, ordinary EPERM, foreign EPERM direct and via symlink with the assigned-via-alias control, the direct-access denial matrix with parent-side state verification, and the uncredentialed version-only reply.
- `SandboxProfileTests`: 62 tests green, including 9 new scoped-profile tests (deny-then-allow order, last-rule position, no DB grants, terminal container denies, defines, #1468 throw, deny-only strict trailer, provider-layering survival).
- Regression gates: the full opt-in app graph (`scripts/test-optin-app-tests-reconciled.sh`) ran on this machine (macOS 27.0.1, arm64) and every suite that completed is green, including the seven named daemon suites, `DaemonScopedSocketTests`, `DaemonRunRegistryTests`, `DaemonRunEndpointTests`, `DaemonScopePolicyContractTests`, the full `AgentSandboxProcessTests`, and `ScopedSandboxGateTests` — 237 suites passed.
