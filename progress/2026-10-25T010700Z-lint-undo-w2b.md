# Generalized page-validity lint — W2b user-facing reversibility

Continuation of `progress/2026-10-24T233000Z-lint-repair-enforcement-w2a.md`.
W2a made repairs enforced and auto-reverted; W2b is the user-facing layer on
top: a one-click **Undo lint fixes** affordance and a **"What went wrong"**
disclosure in the existing Run Details panel. Full suite green.

## Progress

- **`LintPageRecordFacts` (WikiFSEngine).** The W2a host accounting persists
  per-page outcomes as `label=value` text in the queue report's target
  records (schema columns, not blobs — a structured field would need a
  migration). This parser is the single place that knows that text shape: it
  recovers the authority tier, the approval id, the audited (inspected)
  head, the written head, any `revert=` outcome (including the
  `"; FLAGGED for review"` tail segment), and the persisted
  verification-failure reasons. `wroteSurvivingRepair` derives the undo
  eligibility: succeeded record, repair-capable tier, no revert, both heads
  known and distinct. Parser inputs are the exact producer formats, so a
  format drift fails tests first.
- **`LintUndoService` (WikiFSEngine).** The undo batch: one
  `revertPage(pageID:to:expectingHead:)` CAS call per repaired page — the
  SAME seam as the W2a auto-revert, so a moved head is refused
  (`PageConflictError`) and reported, never clobbered — then ONE
  `recordUserUndo` for the run's configuration. The breaker key is
  reconstructed from the durable record's `approval_id` through the shipped
  manifest's approval row (provider/model/effort) plus the live pipeline
  digest; an unknown row or an unreadable manifest records nothing and the
  undo still reverts. The shipped manifest currently carries zero approval
  rows, so breaker recording activates when a real row ships — pinned by
  test.
- **Breaker read API.** `LintRepairBreaker.windowStatus(for:)` returns the
  read-only window counts (verification failures, user undos, trip reason)
  for the disclosure's "N of 2 allowed … used" context line. Read-only — it
  never mutates state, and stale-pipeline files answer as the reset they
  will become.
- **Run Details panel (WikiFS).** `QueueRunDetailsLintRepair` maps a lint
  attempt's durable report into the panel section (pure value; visibility
  rules: report-only and whole-wiki runs map to no section at all,
  budget-rejected runs likewise — they wrote and disclosed nothing;
  auto-reverted runs render the disclosure without the undo row).
  `QueueRunDetailsView` extends its existing List: the "N applied" fixes
  row (only when > 0), the bordered one-click **Undo lint fixes** button
  (hidden after the batch ran — one breaker undo per decision; disabled
  while in flight), the honest aggregate ("Undo: 1 reverted, 1 changed
  since this run."), per-page manual-revert rows with the established
  page-history window link (`openWindow(PageVersionCompareContext)`), and
  the "What went wrong" disclosure: the persisted findings verbatim, the
  reverted diff reusing `SplitDiffView` (written version vs inspected
  version, both durable in page history), the breaker context line, and the
  trip notice ("Auto-repair paused for this configuration: …").
- **ActivityWindowView wiring.** The window owns the undo presentation
  state (reset on selection change) and executes through the session's own
  wiki store — the same store the queue's lint runs and the page-history
  window write through. The wiki being closed reports a per-page failure
  rather than silently no-op'ing. The breaker context resolves only when
  the run's approval id maps back to a configuration; it is a local file
  read, no network, no mutation.
