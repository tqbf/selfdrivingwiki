# Defuddle bundle — fix silent fallback-to-tag-based (#761 regression)

## Progress


**Symptom:** `DefuddleExtractionServiceTests.extractsMarkdownAndMetadata`
and `.extractsSimpleArticle` failed with `Expectation failed: … → nil`.
`resolve()` was non-nil (bun at `~/.bun/bin/bun`, script at `build/defuddle`),
but `extract()` returned nil at runtime — looked like a test-runner
sandbox issue (operator's initial hypothesis).

**Root cause — NOT a sandbox issue, a bundling bug.** The plan/README claimed
`tools/defuddle/defuddle` was "a self-contained CommonJS bundle, no external
`require`s, run directly by bun." This was false. The file was a verbatim
`cp` of `~/.local/lib/node_modules/defuddle/dist/cli.js` (7416 bytes) — the
CLI entry point, whose first 15 lines `require("commander")`, `./node`,
`fs/promises`, `path`, `./utils/linkedom-compat`, `./utils`, `./frontmatter`,
`./fetch`. bun runs the npm-installed script fine (it resolves `./node`
relative to the resolved symlink path, where the sibling `.js` files and
`node_modules/` exist), but the standalone `cp` has no siblings — bun dies
`Cannot find module './node'` (exit 1, empty stdout), `extract()` returns
nil, `#require` blows. The "verified: bun runs it standalone" check in the
plan only worked because the verification used `~/.local/bin/defuddle`
(the npm install path), not the standalone copy.

**Silent blast radius:** the broken 7416-byte file was ALSO shipped at
`build/Self Driving Wiki.app/Contents/Helpers/defuddle`, so defuddle
extraction in the running app has been silently falling back to the
tag-based `HTMLToMarkdown` path since #761 landed. The "zero-regression"
guarantee held by accident — `extract()` returns nil → caller falls back.
Nobody noticed because the fallback is the prior behavior.

**Fix:** `tools/defuddle/defuddle` is now a real `bun build` bundle of
`dist/cli.js` — ~2.45 MB, 351 modules inlined (commander, the defuddle
node/extractor/linkedom modules, all site-specific parsers, etc.).
Genuinely self-contained, runs standalone under bun, no `node_modules`.
`bun build ~/.local/lib/node_modules/defuddle/dist/cli.js --outfile
tools/defuddle/defuddle --target=bun` is the documented update procedure
in `tools/defuddle/README.md`; the false "no external requires" claim is
corrected there and in `plans/defuddle-extraction.md` §0 finding 1 (with a
future-agent warning: do not revert to a plain `cp`, you'll re-introduce
the silent regression).

**Files:**
- `tools/defuddle/defuddle` — replaced 7416 B standalone cli.js with the
  ~2.45 MB `bun build` bundle. **Tracked in git.** `build/defuddle` is a
  gitignored derived copy (regenerated by `build.sh` step "Bundle the
  defuddle readability extractor"); refreshed locally so the test (which
  resolves `build/defuddle` first via `candidateHelperDirectories()`)
  picks up the fix. `build.sh` is unchanged — it just `cp`s whatever is at
  `tools/defuddle/defuddle` into `Helpers/`, so the next `make build`
  propagates the bundled version into the `.app` automatically.
- `tools/defuddle/README.md` — corrected the false premise; documented the
  `bun build` step. Also flagged that macOS ships BSD `readlink` (no `-f`).
- `plans/defuddle-extraction.md` §0 finding 1 + §2.1 — corrected.

**CI impact:** none. CI's test step is `--filter WikiFSCoreTests` and bun
isn't installed on the runner, so `DefuddleExtractionServiceTests` is never
invoked there. The fix matters for local dev + the shipped app.

**Result:** `swift test --filter DefuddleExtractionServiceTests` → 10/10
pass (both previously-failing tests green).

**Build:** `swift test --filter DefuddleExtractionServiceTests`.

Newest first. To get up to speed: read `PLAN.md` then this file.
