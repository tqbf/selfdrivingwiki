# YouTube transcript extractor package — 2026-09-06

## Progress

YouTube transcripts moved into a reviewed extractor package. The direct
subprocess fetch path was deleted; the queue hosts now run the package and
persist installed-package provenance.

Date: 2026-09-06
Branch: `feature/youtube-transcript-extractor-package` (stacked on
`feature/apple-ttml-extractor-package`, PR base `feature/apple-ttml-extractor-package`)

## What shipped

- **The reviewed package.** `ExtractorPackages/YouTubeTranscript` —
  `org.selfdrivingwiki.youtube-transcript` 1.0.0, manifest revision 1,
  protocol revision 3, `network` + `shared-runtime-cache` capabilities, one registration
  (`captions`, kind `youtube-transcript`, MIME `video/youtube`), launched
  through fixed `uv run --script` arguments. Generated by
  `scripts/sync-extractor-packages.sh` from
  `tools/youtube-transcript/youtube-transcript` (copy + generated entry
  point, PodcastTranscript pattern); the source digest is pinned in
  `ExtractorPackages/sources.lock.json` and `--check` compares generated
  bytes. Reviewed digest:
  `8f87ff4a0c8c5fac1d5ff19c6d1dff6a816a27c081fb106de3bc6c92b8c7e1a1`.
- **The script.** `tools/youtube-transcript/youtube-transcript` keeps its
  CLI behavior and gains `run_extractor_protocol`: strict request validation
  before any network work, strict URL normalization (watch, `youtu.be`,
  Shorts, embed, mobile) to a typed 11-char video ID, `youtube-transcript-api`
  fetch with manual-over-generated preference and first-available fallback,
  package-owned named bounds (1 MiB request, 32 MiB output, 64 progress
  frames, 4096 bytes/segment, 200000 segments, 64 KiB output headroom)
  with incremental UTF-8 accounting, deadline checks at five seams, atomic
  Markdown publication with partial-file cleanup, and fixed URL-free
  failure messages. Failure mapping: no captions/disabled/unavailable →
  `unsupported-input`; protocol/path/deadline violations and invalid IDs →
  `invalid-request`; blocked requests, network/library failures, malformed
  or oversized caption data → `extraction-failure`; passed deadline →
  `timeout`. Result metadata reports `toolName`, `toolVersion`, the
  selected caption `language`, and `transcriptGenerated` when the library
  exposes it. No media download, no speech-to-text.
- **Reported metadata schema.** `ExtractorReportedMetadata` gains optional
  `language: String?` and `transcriptGenerated: Bool?`. Additive and
  optional: old frames and old hosts keep decoding unchanged.
- **The typed route.** `ExtractorKind.youtubeTranscript`
  (`youtube-transcript` on the wire) and the canonical
  `youtube-transcript`/`video/youtube` route; `ProcessPackageYouTubeTranscript`
  (provenance-carrying adapter), `prepareYouTubeTranscript()` through the
  provider/services/plugin-factory chain, the generic selection state
  machine (reviewed default, explicit `.none` disables, fail-closed
  unavailable identity), the standard Settings route row ("YouTube
  transcript", `play.rectangle`) with the "No default (disable YouTube
  transcripts)" choice, the `default-routes.json` fresh-install default,
  and the schema/kind-list/doc updates.
- **Queue migration.** `AppQueueExtractionProvider` and
  `DaemonQueueExtractionProvider` resolve `.youtube` through
  `YouTubeSourceURL.resolveOperationURL` (plan URL first — watch, `youtu.be`,
  Shorts, and embed contracts intact; canonical watch URL reconstructed
  from a validated legacy video ID otherwise; nil otherwise, so invalid
  data never launches a package), execute the selected package with
  progress forwarding, and persist `.transcript` origin, exact
  installed-package provenance (revision, registration, protocol revision,
  reported metadata), and the immutable initial source-content version
  link. Re-transcription appends alternatives; failures write nothing.
- **Deletions.** `YouTubeTranscriptService`, `YouTubeTranscriptFetching`,
  `TranscriptSubprocess` (+ their test files), and the
  `YouTubeTranscriptPlugin` registration are removed. `ExtractionTool.youtubeCaptions`
  and its technique mapping remain for historical rows; new results never
  use built-in YouTube provenance. `WikiStoreModel.transcribe` is now pure
  dispatch for `.applePodcast`, `.podcast`, and `.youtube` and throws
  `.transcriptQueueRequired` (renamed from `.podcastQueueRequired`; all
  callers updated). The `youtubeFetcher` parameter and the private
  `transcribeYouTube` direct-write helper are gone; `addURL` lost its
  back-compat no-op parameter.
- **Documentation.** New plan file indexed in `PLAN.md`;
  `docs/architecture/extractor-script-protocol.md` and
  `docs/architecture/extractor-package-manifest.md` list the new kind and
  worked example; `docs/user-guide/extractor-packages.md` and
  `docs/user-guide/sources-and-ingestion.md` describe the route, the
  available-captions-only boundary, and the disable choice;
  `plans/transcript-generalization.md` carries a historical-record banner;
  the tool README documents both surfaces.

## Known limits

- `youtube-transcript-api` uses an undocumented YouTube interface; YouTube
  can change it or block an IP. These surface as bounded typed failures
  (`extraction-failure`), never as silent degradation or audio
  transcription.
- The official captions download API is not a fallback for arbitrary
  public videos (it requires edit permission), so the unofficial dependency
  risk stays, now contained behind the package boundary.
- The maintainer skill text still describes protocol revision 1 kinds; per
  the plan, the architecture docs and validators remain authoritative and
  the skill was not edited.

## Follow-ups

- Vimeo OAuth transcript route (#564 Phase 4) can now mirror
  `YouTubeSourceURL` + the package adapter shape.
- If YouTube blocks a deployment's IP persistently, the route fails closed
  with a typed failure; a proxy/egress strategy is an operator decision,
  not package behavior.
