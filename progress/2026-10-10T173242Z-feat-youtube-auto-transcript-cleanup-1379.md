# feat: auto-extract transcripts at URL import and run the manifest-claimed cleanup agent (#1379)

## Progress

Issue #1379: adding a YouTube URL should auto-run transcript extraction and
then an agent cleanup pass over the raw transcript. The operator extended the
scope: podcast sources get the same AUTO-EXTRACT (their packages claim the
MIME) but NOT auto-cleanup (their manifests do not declare the claim —
publisher transcripts are usually already clean).

**Half one — auto-extract at import (kind-free, registration-derived):**

- `URLFetchService.FetchOutcome` gains `transcriptExtractionWanted` and the
  created `sourceID`. The signal is derived from the ACTIVE registration
  claims the wiring already maintains (`WikiStoreModel.registeredExtractionInputs`,
  fed by `ExtractionBackendRegistry.registeredExtractionInputs()`); the gate
  helper `WikiStoreModel.transcriptExtractionWanted(mimeType:)` names no
  extractor kind. All three byteless creation paths report it: the Apple
  Podcasts branch, `bytelessMediaOutcome` (YouTube/Vimeo/Spotify/SoundCloud/
  remote — whichever of their MIME types a registration claims), and
  `addPodcastFeedURL` for consistency. `addPodcastFeedURL` is currently a
  dormant entry point (no production caller), so nothing auto-enqueues from
  it yet.
- The UI layer that calls `addURL` enqueues: `AddFromURLSheet` takes an
  optional `queueEngine` (wired from `ContentView`) and, when the outcome
  reports the claim, enqueues the standard `.extraction` queue item — the
  same request the manual Transcribe button builds. Sheet UX is otherwise
  unchanged; the existing `QueueActivityTracker.extractingSourceIDs`
  indicators track the item. An enqueue failure is logged through
  `DebugLog.extraction`, never a fetch failure.

**Half two — manifest-driven cleanup (new manifest revision 5):**

- `ExtractorManifestRevision.v5` adds the registration-scoped optional
  boolean `wantsAgentCleanup`. Revisions 1–4 reject the key (unknown-field
  policy); encoding writes it only when set, so every older canonical byte
  stream and package digest is unchanged.
- The claim flows package data → `ExtractorRegistration` →
  `ExtractorRegistrationPresentation` → `ExtractorRouteRegistrationSnapshot`
  → `RegisteredExtractionInputs.Claim`, with a fail-closed lookup
  `wantsAgentCleanup(forNormalizedMIME:)`.
- After `AppQueueExtractionProvider.persistTranscriptExtraction` persists a
  package transcript whose source MIME carries the claim, the SAME provider
  task runs the cleanup: a one-shot model call on a NEW dedicated agent
  stage (`AgentProviderStage.transcriptCleanup`, own scratch world, bypass
  permission policy, summarizer-style lease protocol, `stageProviderIds[
  "transcriptCleanup"]` pin with global-default fallback, Settings →
  Operations → Transcript Cleanup picker). The system prompt is the new
  `prompts/transcript-cleanup.md` — never the wiki-writing ingestion prompt.
- The cleaned copy appends through `appendProcessedMarkdown` with origin
  `.transcript`, note "auto transcript cleanup", technique
  "transcript-cleanup" — append semantics parent it to the current head
  (the raw transcript), which stays in history. Provenance (activity +
  agent rows) attributes the pass like other derived versions. No new
  `SourceMarkdownOrigin` case: `.transcript` + the technique marker matches
  how `appendProcessedMarkdown` already classifies producers and avoids a
  persisted-enum ripple.
- Best-effort by contract: every failure (no provider, turn failure, empty
  output, append failure) is logged through `DebugLog.extraction` and the
  raw head stays canonical; the extraction item still completes
  successfully. No retry machinery in v1. The cleaned copy is skipped when
  it would equal the raw text.
- The agent invocation is injectable: `TranscriptCleanupAgent` protocol +
  `ModelTranscriptCleanupAgent` production conformer, passed to
  `AppQueueExtractionProvider` at both construction sites (the
  `AppProcessPluginCatalog` extraction-provider closure now also receives
  the shared `providerServices`). Tests stub the protocol; they never spawn.

**Package:** `YouTubeTranscript` bumps to 1.1.0 (manifest revision 5,
`wantsAgentCleanup: true`), regenerated by `scripts/sync-extractor-packages.sh`;
the reviewed identity re-pinned in `ReviewedExtractorPackages.swift`
(digest `f2a4ae9a91f8f389c446e1dcd85f388ac6b2492c4f2552c82c1ee9fedcab9b59`).
The podcast transcript packages intentionally do NOT declare the claim.

**Decisions worth remembering:**

- Cleanup runs on its OWN stage, not the chat summarizer's, so the model is
  independently configurable and provenance names the cleanup lane.
- The daemon's extraction provider (`DaemonQueueExtractionProvider`) does not
  run the cleanup pass yet: it receives no cleanup agent. A transcript
  fetched while the daemon transport owns the queue keeps its raw head until
  re-run through the app-local queue. Follow-up, not a v1 gap to silently
  paper over.
- `Schemas/extractor-package-manifest-v1.schema.json` stays the frozen v1
  artifact (revisions 2–4 never updated it); the living contract is
  `docs/architecture/extractor-package-manifest.md`, updated with the
  revision-5 field and an agent-cleanup claims section.
