# Renderer conceptual integrity repair

## Progress

One lifecycle, one session-authority flow, and clear machine, package, and
presentation boundaries. Details follow.

The renderer PRs merged from 2026-08-31 through 2026-09-04 left the live code
with two lifecycles, two session-authority flows, and blurred resource
boundaries. Production used the overlay-era `RendererAttachmentCoordinator`
while `ReaderDOMRendererCoordinator` was documented but unused. The revision-5
`assetRead` contract had no live wiring. DOM package sessions lacked declared
host-navigation authority that full-window sessions had. A validated-package
interface returned host-generated bytes. Availability vocabulary still said
`enabled` although wiki enablement no longer controls availability.

## What changed

- Current interfaces say `available`. `RendererPreparation.availableDescriptors`,
  `availableInstalledDescriptors`, and the render-context wiring now describe
  machine-wide policy. Wiki-enablement list, read, and set requirements left
  the `WikiStore` protocol. Legacy rows and journal payloads stay readable
  through `LegacyRendererWikiEnablementCompatibility`.
- One per-session authority seam. `RendererSessionPreparationRequest` and
  `RendererPreparedSessionAuthority` carry the exact input reader, an optional
  session-private asset reader, declared navigation kinds, the host router,
  and the link policy. Full-window and DOM package sessions build brokers from
  the same prepared value. Helper execution is declaration-gated and split
  from store-backed admission.
- One DOM lifecycle. `ReaderDOMRendererCoordinator` owns one reference-type
  `ReaderDOMEmbedUnit` per placeholder. The geometry message is replaced by a
  narrow lifecycle event. The overlay coordinator, geometry types, viewport
  helpers, and `ReaderRendererFrameBridgeRegistry` are deleted.
- Separated resource layers. Host-composed frame bytes live in a typed
  composer under the reserved `__host__/` namespace. The router delegates
  every other request unchanged to the validated package provider. Package
  validation rejects manifests that declare the reserved prefix.
- Frame origin tokens require exactly 32 lowercase hex characters. URL parsing
  shares the same token invariant.

## Tests

New suites cover availability policy, session preparation (helper gating,
failure fallback, close idempotence), the DOM lifecycle (registration,
budgets, session attachment, scoped teardown), frame-token shape, and frame
resource provenance. Obsolete overlay, geometry, and entry-rewrite suites are
removed. The full suite passes on macOS.

## Verification

`make build` and `make test` pass on macOS. `swift build` and bare
`swift test` pass. Focused renderer suites pass. `git diff --check` is clean.

## Docs

Current plans, the user guide, and both maintainer skill copies use one name
per concept: `available` for machine-valid descriptors, session preparation
for document-specific authority, validated package resource for immutable
package bytes, frame resource for host-composed bytes, and DOM lifecycle for
the live embed state machine.
