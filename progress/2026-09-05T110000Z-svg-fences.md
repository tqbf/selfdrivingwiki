# SVG fences render as collapsible renderer rows

## Progress

The reviewed SVG renderer package now claims the `svg` Markdown fence alias.
A ```` ```svg ```` block renders as the same collapsible renderer row as
```` ```excalidraw ````, with the diagram inside the existing inert-image
viewer.

`RendererPackages/SVG/manifest.json` moved to revision 2 and version 1.0.1 at
both identity fields. It declares one fence claim: alias `svg`, inline MIME
type `image/svg+xml`. No asset bytes changed, so all digests stay as reviewed.
The validator computes the new package hash from the changed manifest.

The host gained no SVG-specific code. The generic claim resolver, disclosure
markup, quoted-title parser, expansion budget, and frame disposal serve the
new alias exactly as they serve Excalidraw, Mermaid, D2, and JSON Canvas.

Users must import version 1.0.1 through Settings → Renderers → Advanced Local
Renderer Package Import. Installed version 1.0.0 does not gain fence support.

Tests landed in four layers. `SVGRendererPackageTests` pins revision 2,
version 1.0.1, the single claim, row markup, an Excalidraw parity control, the
readable-code fallback without a claim, the removed-claimant notice, the
oversized-fence fallback, and the unchanged read-only contract.
`SVGRendererPackageHostedValidationTests` hosts the production reader, clicks
the real row, and asserts image load, byte-exact mounting, isolation, and
frame disposal. `SVGRendererPackageManifestTests` decodes the real manifest in
the always-run target, so CI checks the declaration even though the other two
suites are gated. `RendererPackageDocumentationTests.svgFenceDocumentationMatchesManifest`
derives every documented fact from the parsed manifest.

Two environment facts shaped the tests. First, the Markdown pipeline resolves
CommonMark backslash escapes inside fence info strings before the typed
fence-title parser runs, so a title with escaped quotes arrives already
unquoted and fails the parser; the offline parity test therefore uses a title
with angle brackets and an ampersand, which the existing JSON Canvas tests
prove out. Second, the hosted window reports `visibilityState === "hidden"`,
so WebKit defers the production iframe's `loading="lazy"` load forever; the
hosted test removes the lazy attribute after expansion to emulate a visible
window and documents why.
