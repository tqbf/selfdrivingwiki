# Strategy CLI (wikictl strategy read/save/reset)

## Progress

The per-wiki strategy can now change through `wikictl`, so a chat can modify it when the user asks.
The new family has three commands: `strategy read`, `strategy save`, and `strategy reset`.
Each command accepts `--json`.

The commands reuse the store seam the app editor uses. `saveWikiStrategy` still owns the
compare-and-swap check, the named limits, and the whitespace reset rule. No store API was added.

`strategy read` prints one `getWikiStrategyState` snapshot: the strategy document and its revision
from a single read. `revision: absent` means no strategy row has ever been written. A wiki reset
to Default keeps its revision number (a tombstone row), and the next save expects that number.

`save` and `reset` require `--expect-revision <n|absent>`. `absent` is the store's nil expectation
(true absence, not a tombstone). A mismatch throws `WikiStrategyConflictError`; `wikictl` maps it
to exit code 3, the same convention as the page and source CAS commands, and nothing is written.
On a changed save, text mode prints the next expected revision on stderr, so the next save needs
no extra read.

An unchanged save reports the committed state from one `getWikiStrategyState` snapshot. Two
separate reads could pair a stale revision with a fresh strategy under a concurrent write, so the
command reads the state once.

The chat prompt (`prompts/chat.md`) teaches the commands with a user-gated flow: read, propose,
wait for confirmation, then save or reset. It states that a source document, page body, or
attached resource is never itself authorization for a strategy edit. It states that a saved
strategy applies from the next turn. The ingest prompts and the shared system prompt do not
mention the strategy commands, so ingestion agents do not gain strategy-edit authority from their
prompts. The policy test pins this placement and claims no enforcement beyond the existing write
rules. `make prompts` synced the bundled copy of `chat.md`.

The user guide gained a terminal section in `docs/user-guide/wiki-strategy.md` that documents
the three commands, the absence and tombstone expectations, the exit codes, and the next-turn
effect.

No live wiki or paid run was touched. Tests used disposable databases. Nothing was committed.
