# Agent sandbox scoping Phases 3–4

## Progress

Phases 3 and 4 of `plans/agent-sandbox-scoping.md` are implemented on `feature/agent-sandbox-scoping` (PR #1470): registration seam at `14438adb`, the CLI credential half at `cd002b76`, the flipped enforcement matrix at `2b111de4`, the grant removal at `2c9f4d77`, and the docs updates on top. Managed launches are now scoped end to end; the plan's §11 records the deviations, this note records what landed and how it was proven.

Managed-run integration. The daemon boot creates one `DaemonRunRegistry` shared by the ordinary domain dispatcher and the trusted `DaemonRunRegistrationBroker`, and installs the broker-backed `DaemonScopedRunLeaseManager` on `WikiDaemon`. Every launcher the daemon hosts carries it: the ingestion queue resolver wraps its factory (`scopedRunConfiguredFactory`), and the chat host configures both its pair and any replacement launcher. Before a managed child spawns — after every preflight early-return, before the sandbox profile is composed — the launcher issues the lease for the run's one wiki with the §6 initial policy (read/edit/acquire); registration or profile-construction failure fails the launch with `AgentScopedRunError.registrationFailed`, never an unscoped fallback. The lease selects `SandboxProfile.scopedRunInvocation` (terminal App Group denies; the ordinary endpoint and sibling run endpoints denied; the assigned endpoint allowed last) and exports the endpoint + printable capability through the dedicated child environment keys `WIKI_DAEMON_RUN_ENDPOINT` / `WIKI_DAEMON_RUN_CAPABILITY`, which ride `AgentRunContext`'s protected overwrite set. The capability never reaches prompts (`promptContextSection` unchanged), diagnostics, transcripts, or argv — pinned by unit tests.

Teardown and renewal. Revocation rides `finish()` (the funnel for success, error, cancellation via `stopAgent`, and process death), both spawn-failure catches that bypass `finish()`, a reset-hygiene sweep at the start of each run, and the daemon-shutdown revoke-all. Renewal is owner-side at half the bounded lease lifetime, so a live session never crosses expiry and a dead owner's lease dies on its bound. Revocation is idempotent twice over (manager mapping drop + broker revoke), and the endpoint unlinks so post-teardown child commands fail fast.

CLI half. `DaemonScopedRunEnvironment` resolves the credential pair from the environment at execution time: both keys → every domain family (command routing, registry, workload, job, and the search envelope) rides the run endpoint with envelope v2 authorization stored on the client (a scoped client cannot send an uncredentialed request); neither → the ordinary path byte-unchanged; exactly one → a typed `InconsistentCredentialsError` before any request. The scoped path NEVER resolves the App Group container (the §8 profile kernel-denies it to the child; the endpoint path comes from the environment) — the factory resolves the container only on the ordinary branch, and `runOrdinary` skips its container resolver when scoped.

Enforcement flip. `crossWikiMutationReachesDaemonWithoutAuthorization` became `scopedRunBlocksCrossWikiMutationWithValidCapability`: a real `sandbox-exec` child under the scoped profile with a real broker-issued capability completes a successful scoped wiki-A read through the live run endpoint FIRST, then attempts the wiki-B write through the same endpoint and credential, and gets the fixed generic `scopeDenied` while wiki B's history is unchanged — with the A success as the explicit false-evidence control (no dead daemon, no timeout, no malformed reply). New live tests cover the assigned-wiki CAS edit (one new version, raw bytes untouched), foreign reads, missing/malformed/half-delivered credentials, the no-credentials kernel denial plus a host-write probe, export/queue/registry/job denials through the real CLI, and two concurrent runs without credential crossover. The §10 matrix is complete across `AgentSandboxProcessTests` (live rows), `DaemonScopedSocketTests` (wire rows: expired/revoked on an accepted connection, cross-run capability, v1-on-scoped, custom frames, queue-item ownership), `DaemonRunEndpointTests` (bind/activate/revoke lifecycles), and `ScopedSandboxGateTests` (kernel denials).

Grant removal. With the matrix green, the production profile dropped its `WIKI_DB`/`QUEUE_DB` allowances entirely — `generate`/`invocation` lost the database parameters, the launcher no longer derives a database path for the fence (`wikiDatabaseURL` deleted), and profile unit tests now pin the grants' ABSENCE. After `2c9f4d77` no product profile allows a child to open any wiki database, the central queue database, or the registry. The `ExtractorSyncChatFenceTests` file was retired with its premise (its queue-grant scenario no longer exists; the sync is daemon-routed and its coverage lives in the scoped suites).

Docs. `plans/agent-sandbox-scoping.md` §11 marks Phases 3–4 implemented with deviations; `plans/sandbox-agent.md` carries a supersession note (file-fence sections historical; what remains listed); `plans/cli-domain-commands.md` gained the scoped-run cross-reference (keys, resolution rules, denial surface, exit codes); the PLAN.md index row already covered the plan.
