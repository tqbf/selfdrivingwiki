WRITES — READ THIS FIRST. The wiki mount is READ-ONLY BY DESIGN. NEVER write files under it and NEVER search for a "mutation tool" or test whether the mount is writable — writing the mount fails ON PURPOSE; do not probe it. The ONLY way to create or update content is the `wikictl` command. Call it as `wikictl --wiki <wiki-id> <subcommand> …` — bare `wikictl` is FIRST on your PATH (the PREFERRED FORM in your RUN ENVIRONMENT block). `--wiki <id>` goes BEFORE the subcommand; `--wiki=<id>` is also accepted. If bare `wikictl` is not found, use the TRUSTED ABSOLUTE INVOCATION fallback from the RUN ENVIRONMENT block verbatim — it targets this wiki even if your nested tool moved its working directory or dropped `WIKI_DB`/`WIKICTL`/`PATH` (those are conveniences, not requirements). Deliver every body via a scratch FILE: write it under the SCRATCH WORKSPACE named in your RUN ENVIRONMENT block, then pass `--body-file <absolute-path>`. A file is the robust default for substantial Markdown; short stdin pipes (`--body-file -`) or quoted heredocs (`<<'EOF'`) also work inside the sandbox (temp files are confined beneath your scratch `.tmp`) — prefer the file for anything you may need to retry. Write with:
  wikictl page add --title T --body-file <scratch>/body.md --source <assigned-source-id>:primary
  wikictl index set --body-file <scratch>/index.md
  wikictl log append --kind ingest --title "…" --note "…"
After a write, read it back with `wikictl page get` (the mount lags the database by ~5s, so cat-ing the mount right after a write shows stale bytes). Cross-link pages with [[Page Title]] wiki-links.

**CAS discipline:** Before writing or updating a page, read its current `head_version_id` — run `wikictl page get --json` (the `head_version_id` field) or capture the stderr line in text mode. Then pass `--expect-head <that id>` to `wikictl page add`. On exit code 3 (CAS conflict — the page was edited after you read it), re-read the page once, reapply your edit, and retry. If it fails again, report the conflict rather than looping. Blind upserts (no `--expect-head`) succeed unconditionally with no CAS check, as before.
